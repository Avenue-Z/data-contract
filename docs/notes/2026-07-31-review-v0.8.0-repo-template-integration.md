# v0.8.0 repo-template integration — review record

A retrospective review of the work that shipped to `main` as **v0.8.0**, the change set that makes
`data-contract` adoptable by an Avenue Z repo scaffolded from `repo-template`. It landed on `main`
without the usual pre-merge review, so this note is the review-after-the-fact, kept out of the code
per the [reviewing-someone's-work fallback](../../CLAUDE.md) (already merged to the integration
branch, so the record is a docs-only note rather than inline PR comments).

Reviewer: Claude (Opus 4.8), on Thomas's behalf. Nothing here changed any reviewed code.

## Scope

Everything on `main` between `v0.7.0` and `v0.8.0`, two coherent clusters:

1. **`contract init`** (PR #62) — a new CLI command that scaffolds the mechanical adoption steps
   (contract.yaml + schemas, `raw_drift` marker registration, CI gate wiring) into a consuming
   repo. New private package `contract_core.scaffold` (`plan.py`, `apply.py`, `detect.py`,
   `pyproject.py`, `render.py`, templates), the `init` subcommand in `cli.py`, and ~1100 lines of
   new tests across nine `test_scaffold_*` files.
2. **CI-gate token retirement** (PRs before #62) — `data-contract` went public, so the reusable
   `contract-gate.yml` made `contract-core-token` optional instead of required, dropped the
   fail-fast token step and the checkout token, and added a `git ls-remote` validation for the case
   where a token is still supplied. Doc reconciliation in `consuming-repo-setup.md` and the
   `ci-gate.yml` template followed.

Also in range: the public-API surface note (`__init__.py`, `consuming-repo-setup.md`) now lists
`reconcile`, `events_report`, and `scaffold` as private; `__version__` → 0.8.0; CHANGELOG entry; and
a 2580-line plan doc under `docs/superpowers/plans/`.

## How this was verified

Every claim below was verified by running the code on Python 3.13.7 against the `v0.8.0` tree, not
by reading it. The scaffold logic is deterministic and pure (plan.py takes a filesystem snapshot and
returns a `Plan`; apply.py is the only writer), so it is verifiable by execution, and it was.

- **Suite green.** `pytest` 428 passed. `ruff check .` clean. `mypy src` clean, 23 files.
- **`contract init` end to end, both archetypes.** Scaffolded throwaway consumer repos (src layout)
  and ran the generated tree's own gate against it:
  - mediated (`--source api`): `contract lint` → `OK: 3 boundaries resolved`; `contract reconcile`
    → `OK: 3 boundaries reconciled`. Exit 0 both.
  - file-ingest (`--source file`): `OK: 2 boundaries` for both. The `tests/.gitkeep` placeholder is
    present, so `reconcile --tests tests` finds a dir and, with no raw boundary, exits 0. This is
    the exact failure the placeholder exists to prevent.
  - The "generated tree passes lint + reconcile on the first run" promise holds.
- **dry-run writes nothing.** `--dry-run` printed the full plan report and left the tree with only
  its original `pyproject.toml` (confirmed by `find`). Same code path as a real run, which is the
  design's point.
- **Re-run gap-fill.** Deleted one schema, re-ran with no flags: it `read` the existing
  contract.yaml, `created` only the deleted file, and collapsed the rest to `skipped 4 files
  (exists)`. Idempotent second pass reported `satisfied pyproject.toml`.
- **Flag refusal.** Passing `--system/--platform/--source` while contract.yaml exists refused with a
  named cause and exit 1 (the flags would be silently ignored otherwise).
- **All four marker rungs.** SATISFIED (re-run), APPEND_SECTION (no pytest section → valid TOML
  appended, re-read by tomllib), INSERT_KEY (section present, no markers key → `markers = [...]`
  inserted after the header, valid TOML), and MANUAL (a `markers` array without `raw_drift` → refused
  to edit, printed the hand-registration snippet, left pyproject **byte-identical** by md5). The
  refuse-rather-than-mangle stance is the right call and it is honored.
- **Placeholder drift test is red on purpose.** The generated `test_drift_*` fails with `GENERATED
  PLACEHOLDER`. The generated workflow's `drift` job runs `pytest -m raw_drift` to make that red
  visible, because `reconcile` only AST-checks the marker exists, it does not run pytest. The two-job
  split (gate + drift) is deliberate and correct.
- **`detect_package` guards.** Neither-layout and both-layouts-present both fail with actionable
  messages pointing at `--package`.
- **Generated CI workflow.** Valid YAML; pins the gate at `@v0.8.0`, which equals the installed
  `__version__` used for the dependency line, so the same-tag rule is satisfied by construction, not
  by the author remembering. No `contract-core-token` wiring, consistent with the retirement.

## Findings

At review time (read-only), no correctness defect survived verification: two items to record,
neither a blocker (findings 1 and 2). Acting on them changed that — building finding 1's self-test
*ran* the reusable gate for the first time and exposed **finding 3, a live blocker**: the gate's
`reconcile` step failed for every real consumer. So the honest tally is one real defect (3), one
latent-coupling fix (2), and one confirmed-and-fixed CI bug (1). All three are now fixed and released:
findings 1 and 2 in PR #68 (v0.8.1), finding 3 in PR #72 (v0.8.2), the last verified by the now-live
self-test running green in Actions.

### 1. The CI-gate cluster is unverifiable from here — unconfirmed, not asserted

`contract-gate.yml` is `on: workflow_call` only. Its token-optional branch, the now-unauthenticated
`actions/checkout` of the public `data-contract`, and the `git ls-remote` fast-fail on a
supplied-but-wrong token all execute exclusively inside GitHub Actions. I read them statically and
they are internally coherent (the `set -euo pipefail` + explicit `exit 0` on the empty-token branch
is right; the `git config insteadOf` still carries the `.git`-suffix scoping comment; the CHANGELOG
and `consuming-repo-setup.md` match the workflow). But "coherent on read" is not "ran green." This is
gated on an external trigger, so I flag it unconfirmed rather than claim it passes.

**Follow-up:** confirm on the next consumer PR that actually calls the gate at `@v0.8.0` (a) that the
no-token path clones and installs, and (b) that a deliberately wrong `contract-core-token` fails at
the `git ls-remote` step with the named message, not later inside pip.

**Resolution (PR #68).** Building the self-test to close this turned the "unconfirmed" read into a
*confirmed bug*. The "resolve this workflow's own ref" step read `$GITHUB_WORKFLOW_REF`, which in a
`workflow_call` workflow is the **caller's** top-level ref, not this file's — so a real consumer would
have checked out `data-contract` at the *consumer's* ref (the wrong version when a name like `main`
happens to exist here, a failed checkout otherwise), never the `@v0.8.0` it pinned. Fixed to
`${{ job.workflow_ref }}` (the documented context for the file that defines the current job). A new
`gate-selftest.yml` calls the gate against a committed fixture consumer
(`.github/fixtures/gate-consumer/`) on the no-token happy path — ref → checkout → install → lint →
reconcile. Residual, by construction and noted in the workflow: the self-test can't validate
cross-repo ref resolution (its caller is this same repo on the same ref) and can't assert the
wrong-token `ls-remote` fast-fail (a `uses:` job can't be `continue-on-error`) — (b) and the external
ref path remain confirmable only from a real consumer PR.

The self-test was **parked** (`workflow_dispatch`-only) in PR #68 because on its first run it caught
a separate, more serious bug — see finding 3. PR #72 fixed that and **re-enabled the self-test**; it
now runs the reusable gate against the fixture consumer on every relevant PR and push, green.

### 2. `--platform` / `--system` charset permits `-`, which reaches a pytest module filename

`_validate_identifier` (plan.py) allows `[A-Za-z0-9_-]`. A hyphenated platform (`--platform my-crm`)
produces `tests/test_drift_my-crm_raw.py`, a filename that is not a valid Python module identifier. I
tested it: under pytest 9.1.1 it collects and runs, and the tree still lints and reconciles clean, so
**this is not a live bug today.** It is a latent coupling: the "correct by construction" guarantee for
the drift test leans on pytest tolerating a non-identifier module filename, which is an import-mode
detail, not a contract.

**Follow-up (optional, low priority):** either restrict the drift-test filename stem to identifier
characters (sanitize `-` → `_` when building the test path, independent of the schema-namespace
value), or note in the design that a hyphenated platform is supported only as long as pytest collects
non-identifier filenames. No action needed for correctness now.

**Resolution (PR #68).** Took the first option: `_plan_drift_test` now sanitizes `-` → `_` in the
filename stem only (`test_drift_my_crm_raw.py`), leaving the `raw_drift` marker arg — which
`reconcile` matches on, not the filename — verbatim so it still equals `contract.yaml`. Verified by
execution: a hyphenated platform still generates a tree that lints and reconciles clean.

### 3. The gate's `reconcile` fails for a real consumer — a live bug, found by running the gate

Discovered while building finding 1's self-test (`gate-selftest.yml`), which is the first thing to
actually *run* the reusable gate rather than read it. The gate installs the consumer with its default
`install-command`, `pip install .` (non-editable) — the same command the generated consumer workflow
uses. A regular install copies the package into `site-packages`. The generated `boundaries.py` finds
its `contract.yaml` by walking **up from `__file__`**:

```python
_ROOT = next((p for p in Path(__file__).resolve().parents if (p / "contract.yaml").exists()), None)
if _ROOT is None:
    raise FileNotFoundError(...)
```

From `site-packages` there is no `contract.yaml` ancestor, so import raises `FileNotFoundError`, no
`@runtime.*` decorator registers, and `reconcile` reports the import failure plus every boundary as
undeclared. Reproduced faithfully — consumer at its own root, `pip install .` in a clean venv,
`reconcile` run from the consumer root:

```
RECONCILE FAILED:
  - declared but no decorator registered it: input 'records'
  - declared but no decorator registered it: output 'report'
  - declared but no decorator registered it: raw 'realco_raw'
  - module 'realpkg.boundaries' failed to import: FileNotFoundError
```

This hits **every real src-layout consumer** using the documented flow — i.e. the gate as shipped
does not pass on a real adoption. It slipped through because all prior verification (including this
review's own `contract init` e2e) imported `boundaries.py` from the *source tree*, where the
`__file__` walk succeeds; only a real install exercises the failing path. Pre-existing in v0.8.0; the
PR #68 changes do not touch the boundaries template or the runtime.

**Follow-up (separate PR — this is the fix that re-enables the parked self-test):** make the
consumer's `boundaries.py` locate its `contract.yaml` without assuming it runs from the source tree.
Candidate directions, to be brainstormed: resolve from the current working directory (where the gate
already runs `reconcile --contract contract.yaml`) rather than `__file__`; or thread the contract
path in via an environment variable the gate sets; or make boundary *registration* not require the
contract loaded at import time (validate lazily). Whatever lands should flip `gate-selftest.yml`'s
triggers back on and go green.

**Resolution (PR #72, v0.8.2).** Took the environment-variable direction. `reconcile` now exports
`CONTRACT_YAML` (the `--contract` path it already holds) across the force-import, and the generated
`boundaries.py` reads it — with schemas taken as a sibling — falling back to the `__file__` walk for a
source/editable checkout. Proven three ways: a new e2e test imports the package from a copy *outside*
the repo (the install condition, red without the fix); the full gate flow reproduced locally in a
clean venv (naked import still raises `FileNotFoundError`, but `contract reconcile` → `OK: 3
boundaries reconciled`); and `gate-selftest.yml`, un-parked, runs the reusable gate green in Actions.

## Read

The change is well-built and genuinely well-tested. The reasoning comments are unusually good: every
non-obvious decision (why `.replace()` not `.format()`, why the marker guard refuses rather than
edits an existing array, why file-ingest needs a `.gitkeep`, why gate + drift are two jobs) carries
its own justification at the call site. The plan/apply purity split is what made this reviewable by
execution at all. The token retirement is a clean subtraction: optional-not-removed means no existing
caller breaks, and validating a supplied token turns a silent late pip failure into a named early one.
